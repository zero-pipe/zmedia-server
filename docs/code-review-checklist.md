# 代码评审检查清单

> 配合 `docs/threading-auth-recording-model.md` 使用。模型说"是什么"，本清单说"评审时逐条看什么"。
> 任何一条不满足，PR 不予合入；确有必要的例外必须在提交信息里写明理由。

## 1. 线程与阻塞

- [ ] 新增的调用是否可能运行在 poller 线程上？若是，逐项确认没有：`getaddrinfo`、
      阻塞 `connect/recv/send`、`select/poll` 当等待用、`sleep`、`fopen/fclose/fflush/
      `rename`/`stat`/`readdir`、`join`、跨线程等锁。
- [ ] 延时逻辑用 `zn_poller_do_delay` / `zn_timer_*`，没有 `zb_sleep_ms`。
- [ ] 新增线程或线程池？只允许三种：poller、后台 IO 池（VOD/录制关文件）、协议库强制
      的专用线程（SRT）。其它一律不批。
- [ ] 跨线程访问会话数据前，是否用 `zn_poller_async(io, fn, ctx, 0)` 投递回属主 poller？
      投递失败是否释放 ctx 并放行？
- [ ] poller 回调里是否有无上限的循环（`for(;;)` / 排空队列）？单次 tick 必须设条数上限。
- [ ] 异步任务（HTTP、关闭文件、VOD）完成后，结果是否只在属主 poller 线程落地？

## 2. 生命周期

- [ ] 对象可能在异步回调存活期间被销毁吗？有 `destroy_token` / 引用计数保护吗？
- [ ] 延迟销毁是否只有一个归属者（谁最后完成异步任务，谁释放，且只释放一次）？
- [ ] 会话对象的 `free` 是否只发生在它自己的 poller 线程？
- [ ] `zn_poller_async` 的 ctx 是否堆分配（不能传栈变量地址）？

## 3. 鉴权

- [ ] 鉴权入口只走 `zms_auth_check()`；没有新增 `*_auth_pending`、媒体缓存、
      `destroy_deferred` 这类等待态。
- [ ] 协议侧只负责把 URL 参数摘进 `zms_auth_request.params`，不解析业务字段。
- [ ] 验签路径上没有网络请求、没有查库、没有回调 webhook。
- [ ] 拒绝路径按协议回正确错误码（RTMP `BadAuth`、RTSP/HTTP `403`、SRT 关闭、
      RTP-PS `ZN_ERR_DENIED`）。

## 4. 内存与栈

- [ ] 函数栈帧内新增缓冲总和是否 ≤ 2KB？超过就放堆。
- [ ] 栈上是否出现 `char buf[4096+]`、按协议上限取的定长数组、`alloca`？
- [ ] 定长数组的大小是否对齐协议标准（有依据写注释），而不是"拍个大数保险"？
- [ ] 结构体是否新增 `char x[4096+]` 成员或按值内嵌大结构？单连接/单会话的结构体
      尽量 ≤ 4KB，超了先问能不能拆。
- [ ] 大块数据用指针/arena/按需分配，而不是定长内嵌（参考 `zms_rtp_muxer` 的
      SPS/PPS 懒分配、`zms_http_header.value` 的按需堆分配）。
- [ ] 内嵌缓冲改为指针后，所有 `memset(x, 0, sizeof(*x))` 是否换成了带释放的 clear？
- [ ] 公开头文件里是否有"值类型"却超过 1KB 的结构体？改为不透明句柄 + 访问器。

## 5. 录制

- [ ] 写盘在 poller 上同步进行，没有新增写盘队列/worker？
- [ ] 关文件（`fflush/fclose/rename`/算大小）只在后台 IO 池？
- [ ] 切片只按"时长 + 关键帧"切，临时文件 `.tmp` 关闭后 `rename`？

## 6. 协议实现

- [ ] 新增协议的 URL 解析点是否把查询串透传给鉴权？
- [ ] 错误码、状态机转换是否与协议规范一致（有无注释说明来源）？
- [ ] 入站数据是否有上限保护（单帧、单消息、单会话速率）？

## 7. 构建与验证

- [ ] 改动 `src/protocol/webrtc/` 时，**必须**用远端 WebRTC=ON 的 `build/` 验证；
      本机若关闭 WebRTC，该目录根本不参与编译，本地"构建通过"不算数。
- [ ] 改动 `src/protocol/srt/` 时同理（需 libsrt）。
- [ ] 远端 Release 构建 + `ctest` 全绿；涉及内存改动补 ASan/UBSan 跑一遍。
- [ ] 大规模重命名（字段搬进子结构）后必须全量编译：脚本替换极易吞掉夹在中间的
      无关字段（历史上吞掉过 `destroy_scheduled`、`session_id`）。
- [ ] 同一会话/对象在代码里可能有多处别名（如 webrtc 的 `s` / `sess` / `mut` / `w`），
      重命名时要按"字段名"而不是"变量名"搜索。

## 8. 压测前必须确认的参数

- [ ] `[general] poller_threads` 与并发连接数的关系（单 poller 上的会话数）。
- [ ] GOP 缓存策略：`gop_target_gops` / `gop_cache_sec` 与内存的关系。
- [ ] 单会话出站队列上限（慢消费者只影响自己）：WebRTC rtpq、RTSP UDP、HTTP 发送缓冲。
- [ ] 文件描述符上限、监听 backlog。
- [ ] 内存基线：单会话结构体字节数 × 预期并发（改结构体后重新核算）。

## 9. 错误码与返回值

**背景**：`zn_err_t` 里 `ZN_ERR_NOMEM == -1`，所以裸 `return -1` 在类型上等价于
"内存不足"。历史上不同模块既写 `return -1` 又写 `return ZN_ERR_INVALID`，
调用侧同时出现 `< 0`、`!= ZN_OK`、`== ZN_ERR_*` 三种判断，读代码必须逐个推断。

**规则**（按函数职责二选一，不要混用）：

| 函数职责 | 返回类型 | 失败表示 | 说明 |
|---|---|---|---|
| 业务/生命周期/IO 入口 | `zn_err_t` | `ZN_ERR_*` 具体码 | 调用方据错误码决定重试/拒绝/上报 |
| 解析器（有"已消费字节数"语义） | `int` / `ssize_t` | `<0` | `-1` = 数据不完整，`-2` = 格式错误 |
| 布尔谓词 | `int` | `0` | 只回答是/否，不承载错误细节 |
| "有多少"类查询 | `size_t` | `0` | 0 同时表示"没有"和"失败"，调用方需能接受 |

- [ ] 声明为 `zn_err_t` 的函数，**不得** `return -1`（语义会变成 NOMEM）。
      统一写 `return ZN_ERR_INVALID / ZN_ERR_IO / ZN_ERR_STATE ...`。
- [ ] 解析器类的 `-1` 必须在函数头注释里写明含义（不完整 / 格式错误）。
- [ ] 调用 `zn_err_t` 函数用 `!= ZN_OK`；不要用 `< 0`（会漏掉未来的正数错误码）。
- [ ] 需要区分具体失败原因时用 `== ZN_ERR_*`，不要拿 `-1` 猜。
- [ ] 忽略返回值必须显式 `(void)`，且只允许用于"确实无所谓失败"的路径
      （唤醒、尽力清理）；会丢数据的步骤不许忽略。
- [ ] 新增公共工具函数优先复用 `src/util/`（如 `zms_base64_*`、`zms_hex_decode`、
      `zms_sha1_*`），**不要再自写一份**——历史上 base64 曾有 6 份实现，
      边界处理各不相同。

**已知例外**：`zms_codec_*` 系列、`zm_*` 第三方库沿用其原有约定，不在本规则内。

## 10. 测试

分层测试策略（对应 `tests/`）：

| 层级 | 覆盖 | 入口 |
|---|---|---|
| 单元 | 纯逻辑：解析器、时钟、pacing、编解码封装、配置加载 | `tests/test_*.c`（ctest 默认跑） |
| 风格守卫 | 错误码约定、配置模板一致性 | `tests/check_errno_style.py`、`test_config_ini` |
| 集成冒烟 | 真实进程 + 推流 + 播放链路 | `tests/smoke_e2e.py`（`ctest -L integration`） |

- [ ] 改了 `src/session/` 或 `src/egress/` 的状态机/时间换算，是否有对应单测？
      这两层是并发与时间逻辑最密集处，历史 bug（定时器 ABBA 死锁、G.711 补静音、
      HLS 响应头截断）全部落在这里。
- [ ] 改了协议对外行为（URL 规则、错误码、SDP 字段），是否更新/新增冒烟断言？
- [ ] 修 bug 时先写一个能复现的失败用例；提交信息里说明"移除修复后该用例会失败"，
      证明测试真的覆盖到了。
- [ ] 新增测试不得依赖外部网络、固定端口或素材文件；需要端口的归 `integration` 标签。
- [ ] 测试断言用 `tests/zms_test.h`（不是各文件自带的 CHECK 宏）。数值断言
      必须用 `CHECK_EQ_U32/INT/SIZE/STR`，失败时输出实测值——只打印
      `check failed: ts == 90000u` 的断言对排查毫无帮助。
- [ ] 每个用例 `RUN_TEST_COUNTED(test_xxx)` 注册，main 用 `ZMS_TEST_SUMMARY` 收尾；
      一个用例失败不影响其余用例继续跑。
- [ ] 用例里的注释写"为什么这条边界重要"（例如"recorder 用 UDP 时必现"），
      而不是复述代码在做什么。
- [ ] 被测行为若属于"刻意的宽松解析"（如 `npt=-` 视为从 0 开始），
      用例要有注释说明这是有意为之，防止后人"顺手改成严格"。
